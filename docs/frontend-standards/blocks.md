# Blocks, Entries, and Slotfills

The plugin comes from
[create-wordpress-plugin](https://github.com/alleyinteractive/create-wordpress-plugin).
Its `blocks/` and `entries/` READMEs and `CLAUDE.md` cover scaffolding, the
build, and registration. Generate new files with `npm run create-block`,
`create-entry`, or `create-slotfill` rather than by hand; the generated files
already follow most of the structure and escaping conventions. This file holds
what the generators do not enforce.

Write blocks in TypeScript. Every block has a README: what it does, usage, a
props table, and its styling hooks. `theme-navigation` is the model.

## Dynamic by default

Blocks render in `render.php`, and `save` is omitted or returns `null`. A
static `save` is for structural wrappers around `InnerBlocks` only, with a
reason in the PR. Dynamic output changes without a content migration, which is
why this is the default.

Prefer composing before building: core blocks, patterns, block variations, and
block bindings first. Build a custom block when none of them can do the job.

## block.json

Declare everything declarative in `block.json`, not in JS or PHP. See the
[block metadata reference](https://developer.wordpress.org/block-editor/reference-guides/block-api/block-metadata/)
for the fields. Use `apiVersion: 3`, and reach for a variation before a
near-duplicate block.

The `Register_Block_Manifest` feature registers blocks from the manifest that
`npm run build` writes. Do not call `register_block_type()` by hand.

## edit.tsx

Check `@alleyinteractive/block-editor-tools` for a hook (for example
`usePostById`) before writing your own. Translate every string with `__()` and
the plugin's text domain, the same value as `textdomain` in `block.json`.

## render.php

- Validate attributes and context first, and `return` early on bad input
  ([data-safety.md](../backend-standards/data-safety.md)).
- Escape every value (`esc_html`, `esc_url`, `esc_attr`).
- Logic beyond about 20 lines lives in a class in `src/`, as `Primary_Term`
  does ([features.md](../backend-standards/features.md#keep-it-small)).

Change a block's markup with `WP_HTML_Tag_Processor`, not `str_replace` or a
regex. String edits break on attribute order, whitespace, and nested tags.

Read posts, terms, and meta from context: declare `usesContext` (`postId`,
`postType`, `queryId`) and read `$block->context`.

## Styling hooks

Variants expose a data attribute (for example `data-location="header"`) and
document it in the block README. Other style rules: [styles.md](styles.md).

## Front-end behavior

Block-specific front-end code loads through `viewScript` or
`viewScriptModule`. New interactive behavior uses the Interactivity API.

## Entries

An entry is a directory under `entries/` that is not a block. `create-entry`
generates its script, stylesheet, and enqueue file. Keep an entry's own assets
in its directory, and name the stylesheet `index.scss`.

## Slotfills

Editor extensions are slotfills, generated by `npm run create-slotfill`. Each
pairs with a PHP Feature that registers the meta or REST field the slotfill
reads (see `Subheadline` and `Featured_Image_Caption`).

Declare meta the editor reads in `config/post-meta.json` or
`config/term-meta.json`, with `show_in_rest` set. The plugin registers those
files at load.

## Done

A block is done when:

- `block.json` follows the rules above and validates against its `$schema`
- the README exists
- `npm run build` emits the block into `build/blocks-manifest.php`
- the block renders on the front end and in the editor
- it meets [accessibility.md](accessibility.md)
- `npm test` passes
